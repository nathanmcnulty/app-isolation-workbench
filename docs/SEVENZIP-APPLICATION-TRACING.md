# Fixed 7-Zip execution tracing

The current assessment profile is `aiw.dev/sevenzip-archive-pair/v0alpha2`.
New plans require this revision and the current compiled source commitment.
Retained revision-1 results remain readable under their original contract;
they do not acquire revision-2 measurements. Never restart an old session to
upgrade its evidence.

## What the producer records

The fixed vendor installer and each actual create, test and extract operation
use the existing suspended-process debugger collector. Before resuming a root,
the producer holds its approved code, independently measures its full primary
token and full-width creation time, and assigns its exact owned job. Each
observed process lifetime retains its CREATE/EXIT pairing, creation-event image
observation and same-event-handle image revalidation after exit. Job totals,
active-process count, gaps, termination and debugger fail-stop facts accompany
the trace. Application children are observed rather than matched against the
separate three-helper control allowlist. No parent edges are invented.

The installer has a separate fixed elevated WDAG setup policy and a 90-second
deadline. It runs in a supervised helper; its debugger fail-stop leaves the
receipt-producing agent alive to retain partial evidence. The helper has a
110-second supervisor deadline and exact owned-job cleanup. Its capture uses
an explicit inherited handle list. Setup is common elevated installation,
**not installation inside the AppContainer candidate**. Application and control
token policies remain distinct and reject this elevated setup authority.

Application operations retain their 25-second deadlines; fixed tree controls
retain 5 seconds. The collector's drain remains bounded. The enclosing workflow
has a 300-second wait, application readiness 150 seconds and the existing admin
runner 600 seconds. These are fixed budgets, not caller-supplied commands or
permission widening.

## Retention and comparison credit

Revision 2 requires a complete installer trace and complete traces for observed
application operations before comparison credit. The verifier checks fixed phase
and root path, independently supplied code digest/size, root token/time binding,
all paired lifetimes and images, and exact job accounting. A zero exit code or
empty job alone cannot substitute for these measurements.

Bounded partial traces remain private observations. Dedicated trace stages allow
retention when an ordinary invocation row could not be published; missing output
capture remains missing. Invalid or absent tracing produces incomplete driver
evidence before candidate incompatibility can be considered. Trace overflow is
an explicit refusal. Its source-defined digest, size and cleanup counters survive
in prioritized, bounded private diagnostic metadata; these are not a complete
trace or cleanup proof. Native unsigned exit-code bit patterns are retained correctly.

Numeric PIDs may repeat between sequential operations. Revision 2 retains
such observations and checks all traced lifetimes, including descendants, using
strictly increasing full-width creation times before credit. Repeated or decreasing lifetimes, and reuse involving an
untraced helper, remain uncredited. Revision 1 keeps its original strict PID rule.

The source commitment includes both new trace modules and their module gates.
The raw trace contains private process/account/path information. Existing safe
comparison summaries continue to exclude those details; private diagnostics are
not measurements or recommendations.

## Acceptance status

The producer and verifier have independent static reviews, including fixes for
receipt survival, inherited-handle storage lifetime, exact setup integrity SID,
diagnostic retention and PID reuse. Focused tests cover malformed and missing
traces, phase/code/token/time/image/job contradictions, retained legacy evidence,
overflow and partial publication. Test/build results for a particular checkout
are recorded in the working state and private logs.

**Native application acceptance on this source is pending.** The
[earlier native positive controls](SEVENZIP-CODE-CONTROL-NATIVE-20261106.md)
belong to source `1d966ca`; they do not prove this install/use path. Fresh native
validation must use newly prepared and approved artifacts and a new one-shot
session. No existing VM107 root, transfer, run or evidence may be adopted.

This trace does not prove loaded DLL or memory integrity, broker/out-of-job or
all-host process coverage, candidate-isolated installation, registry enforcement,
GUI/shell behavior, general compatibility or production acceptance. MXC remains
an independent investigation; no classic fallback or permission widening is
authorized. The full [multi-mode acceptance map](MULTIMODE-ASSESSMENT.md) remains
open.
