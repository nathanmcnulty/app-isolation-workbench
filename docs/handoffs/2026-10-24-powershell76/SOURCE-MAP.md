## Additional affected files and semantics

- `crates/aiw-windows-platform/src/msix_worker/system.ps1`: no runtime gate; LocalAccounts, CIM, Task Scheduler COM, Appx all-user and DISM provisioned inventory must execute natively under the selected runtime.
- `crates/aiw-windows-platform/src/msix_worker/lifecycle.ps1` and `research_msix_lifecycle.ps1`: Appx install/query/manifest/uninstall, supervisor-image validation and error inventory; changing the runtime affects the actual application lifecycle, not only tests.
- `crates/aiw-windows-platform/src/research_msix_native.cs`, `research_msix_interactive.cs`, `research_msix_inventory.ps1`: Add-Type/native observer compilation and process identity require revalidation.
- `crates/aiw-evidence/src/msix_lifecycle.rs` validates a fixed Windows PowerShell image in shared receipts. Separate new runtime-bound receipt validation from historical read-only verification; do not globally replace the literal and invalidate genuine old evidence.
- `crates/aiw-runner/src/msix_lifecycle_report.rs` has legacy BOM-aware reading. Preserve original raw bytes/hashes and old receipts. BOM support is data compatibility, not a 5.1 execution dependency.
- `crates/aiw-probe/src/lib.rs` only discovers `pwsh.exe`; discovery is not edition/version/capability validation.
- `crates/aiw-probe/src/msix_worker.rs`, `scripts/vm-msix/proxmox-worker107.sh`, `scripts/vm-msix/tests/test-proxmox-worker107.ps1`, and `gui/tests/display.cjs` contain the current clean checkpoint contract. A newly authorized runtime-equipped baseline requires coherent pins, not mutation of old preparation evidence.
- `scripts/research/Enable-Worker106Management.ps1` explicitly disables every session configuration except Microsoft.PowerShell. Replacing only client endpoint names would fail; any retained management workflow must migrate its allowlist intentionally, without broadening network/endpoint access.
- `scripts/research/Prepare-Worker106Offline.ps1` requires both Windows PowerShell and a hardcoded per-user Store-style 7.6.7 path. Replace the runtime contract, do not simply make that fragile path the new privileged launcher.
- `scripts/worker106-admin/winrm-client.py` calls pywinrm `run_ps`, which itself launches `powershell -encodedcommand`. `copy-client.py` uses default configurations for every execute/copy/fetch; selecting an endpoint for only the initial probe leaves later transfers on the default.
- `scripts/test-control-sandbox.ps1` stages `fixtures/control/guest-baseline.ps1` or `guest-appcontainer.ps1` as `guest.ps1`, then launches Windows PowerShell in a network-disabled Sandbox. No runtime payload is currently staged. A verified offline runtime/native bootstrap is required; bare `pwsh.exe` substitution is not enough.
- Runtime gates also apply to supporting verification scripts, `fixtures/control/verify-*.ps1`, `test-verifier.ps1`, package builders, `scripts/check-local.ps1`, `work-status.ps1`, and direct module import. Generated scripts need guards in the assembled executable source, not merely in a source fragment that may be invoked as a script block.
- Update generated handoffs in `scripts/build-desktop-package.ps1`, `build-preview-package.ps1`, `assemble-signed-desktop-package.ps1`, `.github/workflows/desktop-candidate.yml` and `packaging/preview/README{,-bambu,-interactive}.txt`. Existing hashes/signatures must be regenerated through authorized assembly, never patched on a published handoff.

## Verified platform constraints

1. [PowerShell requirements](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_requires?view=powershell-7.6) support minimum version and Core edition; [prerelease labels](https://learn.microsoft.com/en-us/dotnet/api/system.management.automation.semanticversion.prereleaselabel?view=powershellsdk-7.6.0) require a separate stable-only decision. [Support lifecycle](https://learn.microsoft.com/en-us/powershell/scripting/install/powershell-support-lifecycle?view=powershell-7.6) distinguishes stable supported patches from previews.
2. [Microsoft's migration guide](https://learn.microsoft.com/en-us/powershell/scripting/whats-new/migrating-from-windows-powershell-51-to-powershell-7?view=powershell-7.6#ws-management-remoting) explains that a local PowerShell 7 client does not move the default WinRM session away from the Windows PowerShell endpoint. [Enable-PSRemoting](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/enable-psremoting?view=powershell-7.6) can alter service/listener/firewall/endpoint access, so it is not an innocuous prerequisite check.
3. [Windows PowerShell compatibility](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_windows_powershell_compatibility?view=powershell-7.6) creates a background 5.1 process and may be implicit. Disabling implicit compatibility does not prohibit explicit `-UseWindowsPowerShell`.
4. [Module compatibility](https://learn.microsoft.com/en-us/powershell/windows/module-compatibility?view=windowsserver2025-ps) does not establish an unqualified Appx guarantee on every 7.6/Windows build. Validate the exact native module and OS. [PackageManager](https://learn.microsoft.com/en-us/uwp/api/windows.management.deployment.packagemanager?view=winrt-26100) provides native package APIs if a replacement is needed; [modern C#/WinRT](https://learn.microsoft.com/en-us/windows/apps/develop/platform/csharp-winrt/) is preferable to assuming old direct WinMD activation works in modern .NET. Do not replace current-user deployment with [DISM provisioning](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/sideload-apps-with-dism-s14?view=windows-11).
5. [FileSystemAclExtensions.CreateDirectory](https://learn.microsoft.com/en-us/dotnet/api/system.io.filesystemaclextensions.createdirectory?view=net-10.0) is Microsoft's documented replacement for the removed Framework overload: `[IO.FileSystemAclExtensions]::CreateDirectory($acl, $path)`. It takes arguments in the reverse order and applies the descriptor at creation; it does not repair an existing directory. Preserve existing ACL/reparse/freshness checks.
6. [New-PSSession](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/new-pssession?view=powershell-7.6#-configurationname) documents configuration selection. The [pwsh-first Direct fallback statement](https://learn.microsoft.com/en-us/powershell/scripting/whats-new/differences-from-windows-powershell?view=powershell-7.6#powershell-direct-for-containers-tries-to-use-pwsh-first) is specifically about containers, not proof of Hyper-V VM behavior. No Direct route is present in the inspected tree.
7. Upstream [pywinrm run_ps](https://github.com/diyan/pywinrm/blob/master/winrm/__init__.py) wraps Windows PowerShell; upstream [pypsrp Client](https://github.com/jborean93/pypsrp/blob/master/src/pypsrp/client.py) supports configuration selection separately for execute, copy and fetch. Confirm the repository-pinned versions' exact APIs while implementing.
