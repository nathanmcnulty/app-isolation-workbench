**Title:** Add offline Results Explorer and fixed paired controls to the desktop workflow

The desktop can now open a bounded, explicit selection of retained assessments,
compare application/workflow functions, inspect failures and evidence gaps, and
export privacy-limited JSON/Markdown summaries to new files outside retained
workspaces. Existing report-set verifiers determine results. Failed, not reached
and unmeasured remain distinct; historical cleanup stays separate. Viewing and
exporting cannot execute, cancel, recover or modify a run.

The fixed ordinary-user versus classic AppContainer file, registry and child
controls now use the shared preparation, exact approval, separate Start, lease,
journal, receipt and owned recovery services. Preparation uses static identity
inspection with no provider invocation. Start checks current commitments only
after approval. Results explains baseline/candidate observations, token and
descendant evidence, denied versus missing resources and comparison eligibility.
Broken baselines/drivers and unknown cleanup remain inconclusive.

Validation uses the actual production services with strict fake boundaries and
explicit synthetic receipts, plus the existing reviewed safe archive. It covers
invalid/unapproved dispatch, drift, tampering, duplicate/out-of-order evidence,
partial results, cancellation/interrupted dispatch, exact recovery, stale UI
responses, repeated clicks, hostile text, export failures and keyboard focus.
Independent source review findings were fixed. Final offline Rust/Node results,
formatting, Clippy, governance, exact commits/diff and labeled demonstration are
recorded in [the implementation handoff](PAIRED-IMPLEMENTATION-HANDOFF.md).

No native provider/application/control trial was run; PR #103's completed trials
were not repeated. The guest agent was built and PE-checked but not executed.
Sandbox Tools held-file mapping semantics and the new native workflow require
separately authorized disposable-worker acceptance. See the
[source-pinned proposal](PAIRED-NATIVE-ACCEPTANCE-PROPOSAL.md). General application
compatibility/effective isolation, live Benchmark 2 acceptance and remaining
W4/W5 requirements remain open. No release or production acceptance is claimed.
