# Synthetic paired-control fixture

`synthetic-result.json` is a clearly labeled **synthetic rehearsal**. All user,
package, process and ACL identities are invented. Its placeholder run/request/
profile bindings are replaced by the offline tests with the current typed request.
It is not a retained native run, compatibility result, effective-isolation proof,
or Benchmark 2/W4/W5 production acceptance.

The fixed observations model ordinary-user file/registry reads and a child,
paired with classic AppContainer native access-denied reads and a child. Tests
mutate this model to cover missing resources, native-code confusion, incomplete
drivers, token/resource tampering, duplicate/out-of-order evidence and unknown
cleanup. A missing resource does not become access denied. A failed baseline or
broken driver cannot produce an eligible comparison. Historical cleanup is a
separate observation.

The production request/result normalizer and shared runner kernel process the
fixture through existing fake process/lease/workspace seams. The guest tests also
exercise the real receipt-last publication and completion/evidence verifiers in
fresh temporary directories. No fixture executable, provider, guest account,
AppContainer or application is launched by these tests. Retained source inputs
are read only; per-test files are separate.

Current focused checks (cached dependencies only):

```powershell
cargo test -p aiw-provider-wsb --locked --offline paired_controls::tests
cargo test -p aiw-runner --locked --offline paired_control_tests
cargo test -p aiw-guest-agent --locked --offline paired_
```

The native adapter is source-reviewed and compiled, but no native paired trial
has been run. In particular, held source inspection of Sandbox Tools mappings
requires future disposable-worker validation. The retained paired reader and Results projection/export are implemented. The
admin/desktop preparation/execution controls and full offline product demonstration
remain unfinished at this checkpoint.

The test-only protected fixture rehearsal also uses real protected temporary
workspace/role file identities and the production retained reader/report-set
service. Provider enrollment/readiness, guest tokens, resources and observations
remain synthetic; the inert executable files are never launched. A separate
unknown-cleanup case verifies that viewing neither recovers nor promotes the run.
Optional `AIW_PAIRED_FIXTURE_RETAIN=1` preserves only newly created fixture roots
and emits their explicit selection manifest paths for subsequent read-only demo.
Results summary v0alpha2 exports closed outcomes/flags/hashes only; raw records,
SIDs, process IDs, account identifiers and private paths remain excluded.
